# Agent Control Plane Progress - 2026-04-03

## Summary

Today focused on shipping the first runnable foundation for the Zellij-based agent control plane.

This was intentionally scoped as a transport and command-surface skeleton rather than a full autonomous reviewer loop.

## What Landed

Branch:

- `agent-control-plane-design`

Latest implementation commit:

- `a5cbf8a` `feat: scaffold agent control plane room commands`

User-facing commands added:

- `zellij claude [id]`
- `zellij codex [id]`
- `zellij gemini [id]`
- `zellij reviewer [id]`
- `zellij view events [id]`
- `zellij view code [id]`

Implemented behavior:

- no `id` creates a new shared room ID and prints it
- passing an `id` joins that room if it exists or creates it if missing
- room metadata is persisted under the Zellij cache directory
- participant metadata is recorded for each room member
- reviewer startup writes a fixed bootstrap identity prompt
- reviewer startup writes a fixed review message template
- `view events` and `view code` follow room-owned stream files

## What Is Not Done Yet

The current implementation is a foundation layer only.

Still missing:

- real pane input capture
- real pane output capture
- real command/file-change mirroring into the room streams
- automatic reviewer loopback into the driver agent
- pause/intervene controls such as `Esc`-driven manual takeover
- LAN / WebSocket transport
- richer human-facing event/code UI beyond log-follow mode

## Design Notes Locked In

The interaction model is now intentionally simple:

- the user only needs one shared `id`
- runtime `endpoint_id` stays internal
- provider differences are normalized behind Zellij panes
- reviewer is treated as a first-class participant, not a special hard-coded sidecar

This matches the design direction in [README.md](/Users/chenbiao/zellij/docs/agent-control-plane/README.md).
