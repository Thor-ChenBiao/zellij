## 当前版本状态 (v0.44.14-acp)

### 工作正常
- `zellij claude` 创建房间 ✓
- `zellij reviewer <id>` 加入房间 ✓
- ACP bar 显示房间信息 ✓
- `auto: review:on send:on` 自动启动 ✓
- Auto review worker 进程运行 ✓
- Reviewer 输出 review response ✓
- `acp code <id>` 显示代码内容 ✓
- `acp events <id>` 显示事件流 ✓
- hooks 配置自动注入 ✓

### 已知未解决问题

1. **环境变量传递不稳定**
   - Wrapper script 生成正确但 Claude Code 进程可能不通过 wrapper 启动
   - 旧 session 复用时，旧进程没有环境变量
   - hooks 在没有 `ZELLIJ_AGENT_SHARED_ID` 时静默跳过

2. **Review 闭环未打通**
   - Reviewer 产生了 response，但没有自动注入回 driver 输入框
   - Driver 也没有自动生成 review request 发给 reviewer
   - Auto review worker 检测 driver 活动依赖的事件数据不完整

3. **`acp code` 没有 diff 格式**
   - 显示文件全文而不是 +/- 标记的变更
   - 需要 hooks 传递 old_string/new_string 才能生成真正的 diff

4. **`acp events` 噪音**
   - 大量 `file_hint` 事件（PTY 解析的副产物）
   - 应该只显示 tool call 级别的事件
   - hooks 数据才是正确的来源，但 env 变量问题导致 hooks 不工作

5. **`view code`/`view events` 命令冲突**
   - 系统 `/usr/bin/view` (vim) 优先级高于拦截逻辑
   - 已用 `acp` 命令 workaround

## 下一步建议

1. **优先解决 hooks 数据流** — 确保 Claude Code 进程始终有 `ZELLIJ_AGENT_SHARED_ID`
2. **Review 闭环** — worker 检测到 reviewer response 后自动注入 driver
3. **`acp code` diff 格式** — 从 hooks 数据中获取 old_string/new_string
4. **Events 过滤** — 只显示 tool_call，过滤 file_hint
